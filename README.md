# Agentic Project Template

A lightweight, language-agnostic repository template for AI-assisted software development.

コーディングエージェントを活用した開発において、プロジェクト構造、作業ファイルの管理、Git ワークフローを標準化するためのテンプレートです。

エージェントが勝手に実験して、勝手にブランチを切って、勝手にコードを書いて、勝手にテストして、勝手にワークツリーを整理して、勝手にコミットするような開発環境にするのが目的です。

## Goals

このテンプレートは、次の3点を目的としています。

1. **Consistent Workspace** — プロジェクト間で共通のディレクトリ規約を使用し、一時ファイルや実験コードの氾濫を防ぐ。
2. **Autonomous Git Workflow** — コーディングエージェントがブランチ管理、テスト、コミットを自律的に行い、変更履歴を適切に維持する。
3. **Minimal Agent Instructions** — 共通の開発規約を小さな `AGENTS.md` に集約し、エージェントのコンテキスト消費と設定の重複を抑える。

特定の開発手法や技術スタックを強制するものではありません。プロジェクト固有の事情に応じて、必要な部分を拡張・変更することを想定しています。

## Getting Started

1. GitHub の **Use this template** から新しい repository を作成する。
2. 使用する言語・フレームワークに合わせて、ディレクトリ構造や `.gitignore` を調整する。
3. この `README.md` をプロジェクト固有の概要、セットアップ方法、使用方法に書き換える。
4. 必要に応じて `AGENTS.md` にプロジェクト固有のルールを追記する。
5. コーディングエージェントからプロジェクトを開き、開発を開始する。

2. の手順時には ChatGPT6 Astra や Claude Fable 5 などのハイエンドエージェントと [grilling](https://github.com/mattpocock/skills/blob/main/skills/productivity/grilling/SKILL.md) などの実装計画を詰めるためのスキルを使いながら要件を固め、要件を元にプロジェクトの初期設定をエージェントに行わせるのがおすすめです。

## Directory Structure

| Path | Purpose |
|---|---|
| `src/` | アプリケーション・ライブラリのソースコード |
| `tests/` | 継続的に実行するテスト |
| `experiments/` | 再現・再利用する価値のある実験コード |
| `docs/` | 設計、仕様、技術的判断などの永続的なドキュメント |
| `scripts/` | ビルド、検証、メンテナンスなどの補助スクリプト |
| `.scratch/` | 一時スクリプト、ログ、中間生成物など |
| `.worktrees/` | 並列開発用の Git Worktree |
| `AGENTS.md` | コーディングエージェント共通の作業規約 |
| `.gitignore` | Git の追跡対象から除外するファイル |
| `.editorconfig` | 基本的なエディタ設定 |

`.scratch/` と `.worktrees/` は Git の追跡対象外です。必要に応じて作成されます。

ディレクトリは用途に応じて追加・変更できます。例えば Python プロジェクトでは `src/<package_name>/`、Julia プロジェクトでは標準的な package layout を採用できます。

## Workspace Conventions

### Temporary Artifacts

デバッグ用コード、実行ログ、試行錯誤の過程で生成する中間ファイルなどは、原則として `.scratch/<task-name>/` に格納します。

プロジェクト直下に用途不明の一時ディレクトリを作成することは避けます。

一時ファイルは必要に応じて削除できますが、別のタスクやユーザーが作成したファイルを無断で削除してはいけません。

### Persistent Artifacts

一時的な検証から得られた成果のうち、再利用・再現・保守する価値があるものは、適切な永続ディレクトリに移します。

- **`tests/`**：回帰テストとして継続利用する検証コード
- **`experiments/`**：アルゴリズムの比較、性能評価、再現可能な実験
- **`docs/`**：設計判断、実験の結論、調査結果
- **`scripts/`**：繰り返し使用する開発・運用スクリプト

実験コードとその生成結果は区別します。再現に必要なコードや設定は Git で管理し、大容量のログや一時出力は原則として追跡しません。

## Git Workflow

コーディングエージェントが、日常的な Git 操作を自律的に管理することを基本方針とします。

### Branches

独立した作業には専用のブランチを使用します。

推奨する命名規則：

- `feat/<description>` — 機能追加
- `fix/<description>` — 不具合修正
- `refactor/<description>` — リファクタリング
- `docs/<description>` — ドキュメント変更
- `chore/<description>` — その他のメンテナンス

複数のエージェントが並列に作業する場合は、必要に応じて Git Worktree を使用し、作業ディレクトリを分離します。

### Commits

エージェントは、論理的にまとまった変更を検証した段階で、自律的にコミットを作成します。

- 原則として、一つのコミットは一つの論理的な変更を表す。
- 関連するテストを実行してからコミットする。
- 変更内容を確認し、関係のないファイルを含めない。
- コミットメッセージには Conventional Commits 形式を推奨する。
- 未コミットの変更を不必要に蓄積しない。

### Safety

ローカルでのブランチ作成と通常のコミットはエージェントに委任します。

一方、リモートへの push、保護ブランチへの統合、force push、破壊的な履歴操作などは、別途許可された場合にのみ実行します。

既存のユーザー変更や他のエージェントの作業は、明示的な許可なく破棄・上書きしません。

## Agent Instructions

`AGENTS.md` に、ファイル管理・Git 操作・検証・作業完了時の報告に関する共通ルールを記載しています。

詳細な設計やプロジェクト固有の情報は `docs/` などに分離し、必要に応じて参照することで、常時読み込む指示を最小限に保ちます。

エージェントによって `AGENTS.md` の自動読み込み仕様は異なるため、使用する環境がこのファイルを認識していることを確認してください。

## Maintenance

作業完了時には、以下を基本とします。

- 不要になった一時ファイルを整理する。
- 継続利用する検証コードや知見を永続ディレクトリへ移す。
- 関連するテストを実行し、結果を確認する。
- 変更内容を適切な単位でコミットする。
- 未コミットの変更や未解決の問題があれば報告する。

古い一時ファイルの定期清掃や CI による自動検証は、必要に応じてプロジェクト単位で導入します。

## Design Philosophy

**Standardize the workflow, not the implementation.**

このテンプレートを採用することで開発作業をどのように整理・記録・検証するかという運用面を標準化しやすくなります。

エージェントの自律性を確保しつつ、成果物の再現性、変更履歴の追跡可能性、人間によるレビューのしやすさを維持することを重視します。
